# 协作工作流

团队可以把重复使用的角色分工保存为模板，再为每项需求单独创建任务。Web 和桌面端共用左下角的「协作工作流」入口。

## 新建模板

1. 连接负责执行任务的 T3 环境，在「设置 → Labs」开启 Workflows。
2. 在左下角打开「协作工作流」，点「新建模板」，填写团队容易辨认的名称。
3. 按交付顺序添加角色。为每一阶段写明要处理的材料、交付物和验收条件，例如“根据产品给出的验收编号，逐项写出前置条件、操作和预期结果”。
4. 保存模板。选中模板即可查看阶段顺序和完整职责。模板保存在当前环境，同事连接同一环境后即可使用。已经打开页面的同事可以刷新模板列表。

## 按模板发起需求

选择模板，点「新建需求」，选择已注册的项目，填写本次需求的标题、背景和业务约束，然后点「开始协作」。同一模板可先后创建多项不同需求，每项都有自己的运行编号、阶段记录和结论。工作流运行在选定的项目中，使用该项目可用的默认模型和权限设置。团队如果有账号使用限制，应先在项目中确认模型及其回退设置。

每个阶段获得本次需求和此前各阶段的交付物。角色可以完成交付，也可以写明理由要求上一阶段修订。系统会重新打开上一阶段作者的线程，修订后送回原评审线程复核。首次交付就缺少必要输入，或复核后仍需要返工时，此次运行会停止并保留原因。Agent 执行失败可在原生工作流详情中查看原因和恢复运行。

在模板的任务列表中点击需求，可查看实时状态、启动时的模板快照、各阶段输出、时间线和 Agent 线程。浏览器返回可回到协作模块。查看需要环境的工作流读取权限，新建模板和发起需求需要操作权限。

## 团队与跨设备

模板、需求和运行结果保存在发起任务的 T3 Server。需要多个成员共享实时进度时，把 Server 部署在他们可连接的常驻主机，按权限配对设备，并备份服务数据。另一台电脑单独启动一个新环境会有自己的模板库。开发时从本分支运行 `vp run dev:desktop` 可打开包含此入口的桌面版本。

## 飞书群提醒

团队运维可以对某条需求定时读取运行快照，在退回、暂停、停止、取消或完成时提醒群成员。下面的命令预览待发消息。将 `RUN_ID` 换成需求的运行编号，`TEAM_PAGE` 设为成员能访问的运行详情地址，并使用启动该服务时的 `T3CODE_HOME`。

```sh
node apps/server/src/bin.ts workflow show "$RUN_ID" --base-dir "$T3CODE_HOME" --json |
  python3 examples/pilgrimage-rd/notify.py --page "$TEAM_PAGE"
```

要开启实际投递，配置机器人的 webhook、可选签名和该群的投递记录，按[部署说明](../../examples/pilgrimage-rd/README.md#导出和提醒)运行发送命令。
