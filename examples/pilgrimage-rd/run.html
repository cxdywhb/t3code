目标与角色

  • AC-3：数量为必填正整数；为空、零、负数或非整数时不得提交，并提示填写正整数。
  • AC-4：有效申请提交成功后，粮草官可查看该申请的物品名和数量。

待确认

  • 物品名的长度、空白处理及数量上限。
  • 身份识别和角色权限如何确定。
  • 粮草官查看申请的入口、排列方式及是否展示申请人、提交时间。

限额与并发

每次有效提交在同一数据库事务中执行：

  1. 按队员编号串行化提交（锁定稳定存在的队员行，锁持有至事务结束）；取得锁后读取数据库当前时间，确定业务日期。
  2. 检查该队员的幂等键：已成功则返回原结果，不重复新增或扣额；同键不同内容拒绝。
  3. 创建或读取当日额度行；成功数已为三则拒绝，返回“已达当日上限”，不新增申请、不修改额度。（AC-5、AC-6）
  4. 插入申请并将成功数加一，原子提交；任一步失败整体回滚。额度字段增加零至三的数据库约束。

所有提交路径使用上述事务。剩一个名额时并发请求仅一笔成功；不同队员锁与额度独立。（AC-7）校验失败在事务前返回，不保存、不占额。（AC-9）客户端每次新申请生成新幂等键，连点、超时重试沿用原键；另一次主动申请使用新键。幂等键按队员唯一并随申请保留。

时区与跨日

统一使用时区“Asia/Shanghai”，客户端时间和时区不参与额度判断。以取得队员锁后、额度判断前读取的数据库实际当前时间作为成功申请归属时点，并写入记录；不得使用事务开始时间代替。北京时间每日零点自然切换到新日期额度行，无需定时清零。（AC-8） 跨午夜排队请求按取得锁后的时点归属；午夜前已取得归属时点、午夜后提交成功的请求仍属于前日。重试命中原幂等键时返回原申请，保持原日期。
